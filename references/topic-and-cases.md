# 选题与案例

## 自选题

先把新闻或能力翻译成一件读者愿意看的事。优先回答以下问题，能用几句话说明就不做长表。[E01、E14]

- 哪类读者会关心，具体需求或好奇是什么？
- 我们准备亲自做什么，最终能展示什么？
- 与已有介绍相比，增加了什么体验、判断、方法或避坑信息？
- 案例能否在现有时间和工具条件下完成？怎样用最小尝试验证？

不要只说“提升效率”“降低门槛”。写明谁在做哪件事，原先卡在哪里，AI可能改变哪一步。实用价值和看热闹的趣味都可以成立，不必给每个有趣案例硬造焦虑。

用户要求找热点时，沿用指定发现渠道：X、今日热榜的新闻页 `https://tophub.today/c/news`；综合看知乎、微博、微信、今日头条，科技看36氪、虎嗅、少数派、爱范儿、IT之家。公众号、X、小红书上的高热AI案例可作案例线索。用户给出新来源时按新范围执行，不把发现渠道限制用于事实核验。[E01]

判断内容是否热，应比较同一账号近期表现，不只看绝对点赞或大号体量。用户提出过“高于近期数据50%以上”和多个账号均处于中上水平。注明基准、样本、时间和可得指标；无法取得就说未验证，不补造热度。没有要求完整调研时，不默认启动全平台采集。

热点切入后要回到读者。例如历史数学热点讨论中，用户希望用不同专业、可核对答案的题比较模型正确率和耗时，并连接大众需求；这表明案例应容易解释与执行，不是以后都要做题库评测。[E14]

## 商稿

产品已定，仍要决定故事和案例。先从现有Brief中提取主卖点、必写信息、禁写口径和交付要求；只问真正缺失且影响方向的内容，不要求用户重复填表。[E01]

根据产品和这次传播目标选组织方式：

| 类型 | 可用组织方式 |
|---|---|
| 视频模型 | 用差异明显的场景展示能力，挑能体现本次升级的案例；画质、控制、编辑、成本等由实际材料决定 |
| 生图或设计Agent | 用一套品牌、一个系列或一个完整目标串联，展现一致性、修改与最终交付 |
| 办公或通用Agent | 用真实工作任务写清输入、交付及仍需人工处理的部分 |
| 编程或3D能力 | 从能看见、能玩、能用的成果切入，技术步骤服从普通读者的理解 |
| 随笔式商稿 | 按此次Brief讲观察、体验与看法，弱化逐项测评，不强塞多案例结构 |

这些是优先选项，不规定案例数量。EvoX主案例已详细展示过程，后两个案例就应压缩，补充新亮点；豆包工作的后续Brief改成随笔，也应随之调整。[E06、E08]

## 交付方案

每个方向用一个短标题，加一段说明“从哪里切入—做什么—看什么结果—读者获得什么”。有明显差异时给几个备选并说首选理由，不默认输出复杂评分表。

已经有大纲或跑好的案例时，优先把它们组织好。不为了证明新卖点反复追加实验。实际结果不理想时可以换切口、记录问题或舍弃素材，不能替它补出成功效果。
