# 编辑偏好

这些是从用户实际要求中整理的默认偏好，当前任务可以覆盖。证据编号见 [证据索引](evidence-index.md)。

## 读者与账号

目标读者以25—40岁、一线及新一线互联网和相关行业人群为主，兴趣包括科技、财经、汽车、游戏、房产及工作生活中的AI应用。不要把“互联网人”理解成程序员或建模师。历史署名出现“路人甲”，但不自动给每篇文章添加署名或口播口号。[E01]

写作站位通常是亲自尝试的使用者，和读者一起看结果、判断哪里有用。未实测的资讯稿则保持观察者身份，明确演示来自谁。[E10]

## 默认偏好与条件

| 默认偏好 | 条件与例外 |
|---|---|
| 自选优先案例实践，带来认知或干货 | 用户指定观点资讯就写资讯；不能假称实测，也不能因无法实测否决用户已定文体 |
| 效果强的案例尽早展示 | 负面效果也能形成钩子；没有合格的图不强行放集合图 |
| 大众能看懂，少术语 | 关键概念需准确解释；易读不等于省掉陌生工具的铺垫 |
| 自然、随性，适当调侃 | 随笔、商稿、严肃评价的强度不同；不每段塞梗，不强行粗口 |
| 有真实感受和个人观点 | 未提供的偏好不能安到作者身上；可以提出措辞候选，但不能捏造经历 |
| 精简描述、压缩前摇 | 用户也说过内容太单调、结尾太短；按段落作用调整 |
| 结尾有体验、有判断 | 不默认升到时代意义；本文已展开的趋势可以简短延伸 |
| 多给不同标题方案 | 必带产品名、竞品、价格等是单篇要求；不把一篇条件套到下一篇 |

## 协作习惯

- 用户说“稍作充实”，扩充必要衔接和关键内容，不加一整套框架。[E02]
- 用户说“逻辑不变”“只改这句”，保留主线、分节及前后语气，只解决指定问题。[E03、E11]
- 用户说“先探讨思路、不用完整写”，先给方向。等用户转为要稿，再写成段落。[E12]
- 用户给参考文，是让你理解钩子、表达或结构，不是允许逐句仿写。参考作者的经历和数据也不属于用户。[E02]
- 修改时遵守最新状态。用户从比较两版改为一起评价，就不再写优劣对照；用户撤图，稿中也撤掉相关引图句。[E02、E12、E13]
- 需要判断时直接指出问题，给可用改法，不用每次附长篇写作原理。

## 规则不可越界

不要把旧文档中助手增加的固定评分线、固定案例数、审批流程当作用户硬要求。不从未被否定推断“用户喜欢”；分叉里的相同内容也不算多次独立认可。

产品价格、版本、费用、排行榜、福利、效果和测试耗时随时间变化。本资料保存编辑经验，不维护产品事实库。
