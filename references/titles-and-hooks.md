# 标题与钩子

先读用户给出的全文或明确的选题信息，找出本篇最有吸引力且能兑现的一件事。不要只看开头关键词就批量起名。

## 大标题

先识别本篇约束：必须出现哪些词，想突出什么，哪些角度已经被否定。只有本篇要求才是必带项。

按适合的阅读动机发散，选其中几类即可：

- 具体成果：做出什么读者能立即想象的东西。
- 读者收益：对打工人、创作者或某类使用者有什么帮助。
- 反差与好奇：期待与结果、外观看着好与实际使用之间的差别。
- 亲测判断：测下来最值得记住的结论，含真实不足。
- 热点与调侃：借大众熟悉的话题，把作者这次行动串起来。
- 工具资源：教程、插件集合或方法的独特增量，尤其用户自己做出的资源。

给出的方案应有角度差异，不是同一句话换动词。用户已给方向，就沿其意图拓展，不回到刚被否定的路线上。方案较多时标少量首选及简短理由；没有数据就只能判断吸引力，不能保证流量或称为验证过的爆款。

## 历史案例校准

这些是本篇要求或候选，不能推广成通用标题公式。出处见 [证据索引](evidence-index.md)。

| 案例 | 用户提出的方向 | 复用的是判断 |
|---|---|---|
| Astra 3D | 不想写成“Astra操控Blender保姆级教程”；后来提出史密斯吃面的点 | 避免专业名词劝退，寻找大众熟悉的效果反差；不是永远不能写3D |
| 手机配件 | “别等华强北了，我先给iPhone Duo把配件配齐了”等用户候选 | 热点、具体行动和调侃能结合；不是已采用标题或真实商业合作 |
| 豆包工作 | 不必每个都提收费；希望打工人、情绪词，后来要求Codex和豆包都出现 | 随用户最新标题目标换焦点；开头争议不必成为标题主轴 |
| MiniMax H3 | 必带产品名，突出一手实测、商用；后续强调便宜和与Seedance的对比 | 产品、优势及比较范围服从本稿证据，不复制旧价格 |
| EvoX | “大厂产品之外，Evox让我看到了Agent新的可能性” | 用户给的是个人发现和观点，不只要功能清单 |
| DSH插件 | 自制优质插件集合市场、怎么装、怎么做 | 把作者自己提供的资源增量写进阅读理由，不照搬已有标题 |

## 小标题

先确认分节。不要把用户同一部分拆成两节，也不要给每几个自然段加一个标题。[E05]

小标题应大体概括下文，并自然把读者引过去。可以是具体任务、阶段变化或简短评价；避免每节都用“一句话，重新定义……”之类空话。用户明确“不写小标题”，就不加。[E03、E06]

## 开头钩子

标题、开头和首个素材共同承诺同一个阅读收益。钩子不一定靠夸张，也可以是一次真实失败、一项意外结果或读者本来就有的疑问。

用户说“不够抓人”时，先调整切入和悬念，而不只是增加感叹号、极端形容词和多个问题。调侃要贴着素材；不要为套一个强钩子保留已撤掉的图、过时事实或未完成结果。[E13]

微信公众号标题和短视频标题分开判断。历史短视频的“30秒学会”“1分钟看懂”只有在本稿交付能兑现且用户需要时才考虑，不作为公众号默认表达。
